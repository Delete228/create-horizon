# Create 0.8 release audit

The behavior reference is Java Create 6.0.10 on Minecraft 1.21.1. The development
client uses Horizon Nightly `2ebf00a` plus the three patches listed in
[Validation](../../VALIDATION.md). Earlier evidence is retained there alongside
the checks for this audit.

## Belt rider contact

The [dry horizontal fixture](../../tools/belt_rider_checks.py) checks forward
and reverse travel, centering, crouch, walking, and wall clipping. The local
rider also stays still during a world freeze and three explicit server steps,
then resumes at the same speed when the world unfreezes.

The [slope fixture](../../tools/belt_slope_rider_checks.py) measures 14 ticks
on each of four dry lanes in Java Create 6.0.10. Both axes and travel
directions cross a chunk boundary at 32 RPM. An experimental Horizon adapter
matched the initial contact, then ran up to 0.293 blocks ahead uphill. Its
server calculated the first velocity update from the player's pre-Belt
position and sent a downward velocity of 0.0784 blocks per tick. Java first
moved its server-side player with the Belt and sent 0.0131. The current
Horizon tick callback does not persist a change to the server player's
position or ground state, so the experimental adapter was removed.

## Moving Slime impact

The [local player fixture](../../tools/rotary_slime_player_checks.py) drops a
player onto a single centered Slime block on an upright Mechanical Bearing.
Java and Horizon produce an upward velocity of 0.3910253 blocks per tick at
the same height. The same impact occurs once while server poses are held
for three client ticks. The short drop and crouched drop settle on the
Slime at the same height as Java. The Stone control has no rebound.

## Chunk ownership

The source cells, landing cells and persisted moving record share a loaded
16×16 chunk column in the current adapter. The column spans the world's height.
Mechanical and Windmill Bearings and Rope Pulleys accept up to 2,048 eligible
plain blocks. Bearings require every snapped pose to fit. A vertical dry
Piston accepts the same total with its head and poles included. A Gantry
counts its carriage and checks the cargo footprint at both rail ends.
Other cargo and drivers have a 64-block bound. A Clockwork Bearing uses one
record per hand, with a common limit of four records in the column.
An oblique rotary pose can enter a loaded neighbor while the source and all
snapped positions stay in the owner column.

Java's default maximum is 2,048 blocks for its normal contraption search. The
limit is configurable and Java checks that the affected positions are loaded.
It does not require them to share a column.

[The region-boundary fixture](../../tools/contraption_column_boundary_checks.py)
separates capture with source cells in two regions from capture where only a
snapped landing would enter the other region. Both are valid in Java. Horizon
refuses them before altering the source. The fixture checks both saved columns
after a cold restart.

[The filled tank boundary fixture](../../tools/bearing_tank_boundary_checks.py)
moves a 2×2×2 Tank with 19,000 mB of water in Java. It crosses the region
boundary at capture or at landing, with eight parts restored in either case.
With a bedrock block occupying the far upper corner, Java restores seven parts
and keeps the water in the relocated controller. A 65-block arm can capture
from or land in a column that `/execute if loaded` reports as unavailable
before the respective operation. The Horizon fixture verifies that refusing
cross-region movement leaves all eight parts and 19,000 mB in place. It unloads
each neighboring column independently, reloads both and restarts the process.
Neither region has a saved moving record or mounted fluid for the refusal.

Horizon currently queues each changed chunk as a separate record. Waiting for
those records to save does not make them a transaction. Extending the adapter
requires a durable operation covering the moving record, all edited columns,
and their inventory and glue changes. Recovery must finish or roll back the
operation before the world streams either side. Test crashes between writes
and after the final write, as well as unload and restart, across an Anvil region
boundary. Keep reading old single-column records.

## Release gate

1. Re-run the audit fixtures on the candidate build. Keep the build receipt
   with the Java and Horizon results and the manual review world.
2. Once the upstream state-dependent light declaration is available, build
   the registry artifact on the official Nightly that contains it and verify
   a fresh Launcher install. Exercise original local JAR resources and the
   bundled resources separately.
3. Compare the installed artifact with the candidate. Run a cold world reload
   and the affected behavior and settings checks before submitting the update.
